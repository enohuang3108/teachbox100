# ADR-0001：題庫格式抽成全站共通

- 狀態：已接受
- 日期：2026-09-20

## 脈絡

大富翁的題庫型別（`Question`／`choice|boolean|short`／`Difficulty`）與 Excel 解析
（中文表頭 `題型／題目／選項A-D／正確答案／解析／難度`）住在 `lib/monopoly/`。

新單元「領地戰」要用同一套題目。之後還會有第三、第四個要出題的單元。

老師的期待是：**在大富翁匯入用的那個 Excel 檔，拿到領地戰也匯得進去。**

## 決定

把型別、`parseQuestions`、範本產生與 AI 提示詞搬到 **`lib/questions/`**，
成為全站共通的檔案格式契約。`lib/monopoly/` 改為 re-export，既有 import 不動。

**只共用格式與程式碼，不共用資料。** 每個單元照舊把老師匯入的題庫存在自己的
zustand persist 包裡（大富翁是 `monopoly-game`），不做跨單元的題庫 store。

單元可以只支援格式的子集：領地戰需要能自動判對錯，所以不收 `short`（簡答），
匯入時**略過並提示**，不是整份退件 —— 老師很可能直接拿大富翁的題庫檔過來。

## 取捨

| 方案 | 為什麼沒選 |
|---|---|
| 新單元直接 import `lib/monopoly/*` | 「領地戰」在程式上永遠依賴大富翁，改大富翁會炸兩個單元 |
| 各單元複製一份解析 | 兩份會分岔的 Excel 格式，老師的檔有一天會只在一邊匯得進去 |
| 抽出共用的題庫 store（跨單元同一份資料） | 要對老師既有的 localStorage 做不可逆 migration，換到的好處只是少匯入一次。等真的有人抱怨再做 |

## 後果

- 題庫格式變成跨單元契約，改欄位要同時想到所有用它的單元。
- `CONTEXT.md` 的「題目／Question」從大富翁章節升格成平台層詞彙。
- 老師在兩個單元各匯入一次同一個檔；這是刻意留下的不便。
